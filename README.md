# Clinical Scribe BYOC

Clinical Scribe is a demo AI agent for hospitals. A clinician records or pastes a patient encounter. The agent reads the patient's chart from a FHIR server through an MCP server, then drafts a SOAP note that cites every chart fact. The clinician edits and signs the note, and the agent writes it back to the chart. Every chart read and every signature is recorded in an audit log.

The whole data plane is packaged as Helm charts so that a control plane can install it into a hospital's own cloud account. The database connection and the model provider are inputs to the chart.

All patient data in the demo is synthetic and is generated by Synthea.

## Components

| Chart | Purpose | Image |
|---|---|---|
| `fhir-server` | HAPI FHIR R4 server. It stores clinical data in the external Postgres database. | `hapiproject/hapi` |
| `fhir-mcp` | MCP server that exposes FHIR read tools and one note write tool. | `services/fhir-mcp` |
| `speech-to-text` | faster-whisper transcription with an OpenAI-compatible endpoint. | `services/speech-to-text` |
| `llm-server` | Optional vLLM server for a self-hosted model. It is disabled by default and needs a GPU. | `vllm/vllm-openai` |
| `scribe-agent` | Agent API and clinician web UI. It stores drafts and the audit log in Postgres. | `services/scribe-agent` |
| `synthea-loader` | Job that generates synthetic patients and loads them into FHIR. | `services/synthea-loader` |
| `clinical-scribe` | Umbrella chart that installs the components above and passes shared inputs to them. | |

Each component chart can also be installed on its own.

## Architecture

```
 Clinician browser
        |
        v
 scribe-agent (API + UI) ----> Postgres (drafts, audit log)
   |        |        |
   |        |        +--> speech-to-text (Whisper)
   |        |
   |        +--> fhir-mcp (MCP over HTTP) --> fhir-server (HAPI) --> Postgres (FHIR data)
   |                                              ^
   |                                              |
   |                                       synthea-loader (Job)
   v
 Model provider
   anthropic:          Claude API
   openai-compatible:  llm-server (vLLM) in the cluster, or another endpoint
```

The agent offers only the read tools to the model. The `create_clinical_note` write tool is called by the agent's API after a clinician signs the note, so the model cannot write to the chart on its own.

## Chart inputs

### Database

The umbrella chart takes one Postgres connection under `global.database`. Both `fhir-server` and `scribe-agent` use it. Either component can override any field under `<component>.database`, for example to put FHIR data in its own database.

| Value | Default | Description |
|---|---|---|
| `global.database.host` | none (required) | Postgres hostname or IP address. |
| `global.database.port` | `5432` | Postgres port. |
| `global.database.name` | `clinical_scribe` | Database name. |
| `global.database.username` | none | Username. It is required unless `existingSecretUsernameKey` is set. |
| `global.database.password` | none | Password. The chart stores it in a Secret. |
| `global.database.existingSecret` | none | Existing Secret to read credentials from instead of `password`. |
| `global.database.existingSecretPasswordKey` | `password` | Key in the existing Secret that holds the password. |
| `global.database.existingSecretUsernameKey` | none | Key in the existing Secret that holds the username. |
| `global.database.sslMode` | `require` | `disable`, `allow`, `prefer`, `require`, `verify-ca` or `verify-full`. |
| `fhir-server.database.jdbcParams` | none | Extra JDBC URL parameters for HAPI, such as `currentSchema=fhir`. |

HAPI creates its own tables on first start. The agent creates `scribe_drafts` and `scribe_audit` on start. The database user therefore needs permission to create tables.

### Model provider

| Value | Default | Description |
|---|---|---|
| `global.llm.provider` | `anthropic` | `anthropic` uses Claude through the Anthropic API. `openai-compatible` uses vLLM or another compatible endpoint. |
| `global.llm.model` | provider default | `claude-opus-5-5` for `anthropic`. `Qwen/Qwen2.5-7B-Instruct` for `openai-compatible`. |
| `global.llm.apiKey` | none | Claude API key. It is required for `anthropic` unless `existingSecret` is set. |
| `global.llm.existingSecret` | none | Existing Secret that holds the key. |
| `global.llm.existingSecretKey` | `api-key` | Key in the existing Secret. |
| `llm-server.enabled` | `false` | Installs vLLM in the cluster. Enable it with `provider: openai-compatible`. |
| `scribe-agent.llm.baseUrl` | `http://<release>-llm-server:8000/v1` | OpenAI-compatible endpoint when `llm-server` is not used. |
| `scribe-agent.llm.claude.effort` | `medium` | Claude thinking effort: `low`, `medium`, `high`, `xhigh` or `max`. |
| `scribe-agent.llm.claude.fallbacks` | `true` | Lets the API rerun a declined request on a fallback model that it selects. |

With the `anthropic` provider, transcripts and chart excerpts are sent to the Anthropic API for inference. The FHIR store, audit log, audio and transcription stay in the hospital account. With `openai-compatible` and `llm-server.enabled=true`, inference also stays in the hospital account.

The umbrella chart has a `values.schema.json` that validates the database and model inputs, so a control plane can render a form from it.

## Install

Build and push the four first-party images, then package the chart.

```bash
make push REGISTRY=ghcr.io/your-org
make charts
```

Install with Claude as the model:

```bash
kubectl create secret generic clinical-scribe-db \
  --from-literal=username=scribe --from-literal=password='...'
kubectl create secret generic claude-api-key --from-literal=api-key="$ANTHROPIC_API_KEY"

helm install scribe dist/clinical-scribe-0.1.0.tgz -f examples/values-claude.yaml
```

Install with a self-hosted model on a GPU node pool:

```bash
helm install scribe dist/clinical-scribe-0.1.0.tgz -f examples/values-self-hosted.yaml
```

Open the UI:

```bash
kubectl port-forward svc/scribe-scribe-agent 8080:8080
open http://localhost:8080
```

## Local test on kind

The local profile uses a throwaway Postgres in the cluster and a small model served by Ollama on the host.

```bash
ollama pull qwen2.5:3b
kind create cluster --name clinical-scribe
make images
for s in fhir-mcp scribe-agent speech-to-text synthea-loader; do
  kind load docker-image --name clinical-scribe clinical-scribe/$s:0.1.0
done
kubectl create namespace scribe
kubectl -n scribe apply -f examples/dev-postgres.yaml
helm dependency update --skip-refresh charts/clinical-scribe
helm install scribe charts/clinical-scribe -n scribe -f examples/values-kind.yaml
```

To test the Claude path locally, add `--set global.llm.provider=anthropic --set global.llm.model= --set global.llm.apiKey=$ANTHROPIC_API_KEY`.

## Demo flow

1. Pick a patient in the left column. The synthea-loader Job must finish first.
2. Click "Load sample encounter", or upload an audio file and click "Transcribe audio".
3. Click "Draft note". The right column shows each tool call while the agent reads the chart.
4. Review the draft, including the "Flags for clinician review" section, and edit it if needed.
5. Click "Sign and save to chart". The note is written to FHIR as a `DocumentReference`, and the audit log shows the chart reads and the signature.

## Compliance

This project is a demo. It runs on synthetic data and has not been assessed for HIPAA or any other regulation. A production deployment needs, at a minimum, authentication for the UI, network policies, encryption with keys the hospital controls, and a business associate agreement with each vendor that processes PHI, including the model provider when `anthropic` is used.
